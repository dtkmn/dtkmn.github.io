## What it is

Loopwright is a Python package and local web runtime for inspecting AI answer loops. It routes
context, retrieves evidence, drafts an answer, runs checks, records verifier decisions, and handles
retries and refusals. A typed `LoopReport` preserves that activity for inspection after a run ends.

The FastAPI app supports local threads, indexed files, saved loop recipes, a loop timeline, and
historical run inspection. Ollama is the recommended local model runtime; an OpenAI-compatible
backend supports other deployments.

## Evidence and verification

Context can come from web snippets, indexed files, thread memory, or direct model knowledge.
Prompt-used web snippets and indexed-file chunks count as retrieved evidence. Memory and direct
model knowledge remain unverified when no supporting retrieved evidence exists.

Reports preserve the evidence and verifier provenance needed to assess a result. A verifier result
is a recorded check, not a guarantee that the answer is correct.

## Durable reports and offline inspection

The local app stores run records in SQLite so historical runs can be reopened after a restart.
Public views are projected from the canonical report. Malformed records or older records lacking
required answer/evidence provenance can be quarantined from public inspection; the
[README](https://github.com/dtkmn/loopwright) documents the compatibility boundary.

Local JSONL export writes raw loop reports for offline inspection through `src.loop_replay inspect`.
The inspector does not need a model or the app database. Semantic diff remains planned.

Raw reports can contain prompts, retrieved excerpts, draft outputs, and final answers. The public
projection minimizes fields, but it is not authentication or a general secret-removal mechanism.
Even public exports may contain sensitive answers and provenance, so review an artifact before
sharing it.

## Framework exports and maintenance

The OpenAI trace-shaped and LangGraph manifest adapters export JSON without importing or executing
those framework SDKs. Microsoft Agent Framework remains a future export target. See the
[adapter guide](https://github.com/dtkmn/loopwright#framework-adapter-strategy) for supported mappings.

The repository declares dependencies in `pyproject.toml`, locks them in `uv.lock`, and installs with
`uv sync --locked`. Weekly Dependabot updates and lockfile audits maintain that baseline. See the
[maintenance guide](https://github.com/dtkmn/loopwright#security-and-dependency-maintenance) for the
current commands.

## Scope

Loopwright focuses on recording and inspecting bounded answer loops. Saved recipes and report
exports do not grant tool permissions or provide scheduling. It is not a general multi-agent
orchestration framework.
