## What it is

`mcp-gateway-core` provides JDK-only contracts for MCP tool identity, access rules, policy, audit,
abuse protection, URL scoping, and rate limiting. The optional `mcp-gateway-spring-webflux` adapter
applies them to Spring WebFlux HTTP traffic.

Hosts own authentication, transport, tool execution, storage, and observability. For example,
[MCP ZAP Server](/projects/mcp-zap-server/) owns scanning and findings; Gateway Core does not run
scans, store findings, or provide a proxy data plane.

## Get started

Published libraries target Java 17+; building the repository requires JDK 25. The optional adapter
targets Spring Framework 7, Spring Security 7, and Jackson 3. Older stacks can use the core with
their own transport integration.

Follow the [Getting Started guide](https://danieltse.org/mcp-gateway-core/guides/getting-started/)
for dependency coordinates and wiring examples. Check the
[compatibility guidance](https://danieltse.org/mcp-gateway-core/reference/compatibility/) and
[security support policy](https://danieltse.org/mcp-gateway-core/project/security/)
before choosing an adapter version.

## Current public preview

As of October 1, 2026, the latest published release is `0.11.0` for both the
[core](https://repo1.maven.org/maven2/io/github/dtkmn/mcp-gateway-core/0.11.0/) and
[Spring WebFlux adapter](https://repo1.maven.org/maven2/io/github/dtkmn/mcp-gateway-spring-webflux/0.11.0/).
These are public-preview APIs subject to compatibility changes; development snapshots are separate. See the
[release notes](https://github.com/dtkmn/mcp-gateway-core/blob/main/docs/RELEASE_NOTES.md)
for API additions, protocol corrections, and migration requirements.

<a id="unreleased-development"></a>

Active-tool availability checks are opt-in: hosts must supply the registry, keep permission mappings
consistent, and authenticate before the governance filter. Upgrading the dependency alone does not
enable that integration. MCP ZAP Server `v0.13.0` consumes Gateway `0.10.0`, without the `0.11.0` additions.

## Security verification

The [Snyk workflow](https://github.com/dtkmn/mcp-gateway-core/blob/main/.github/workflows/snyk.yml)
reports scan execution separately from vulnerabilities. A successful scan can coexist with a failing
**Snyk vulnerabilities** status; assess the findings as well as execution. Consumers remain responsible
for their own dependencies and security configuration.
