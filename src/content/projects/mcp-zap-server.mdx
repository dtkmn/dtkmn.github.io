## What it is

This project turns OWASP ZAP into an MCP-accessible security tool so an AI agent can import API
schemas, run scanning workflows, and pull structured findings without falling back to brittle shell
scripts.

## Why it matters

Many MCP demos stop at convenience. This one is stronger because it sits on a real operational
boundary: security automation. The interesting question is not whether an agent can call a tool. It
is whether that tool can be exposed in a way that is safe enough, observable enough, and packaged
well enough to fit into actual engineering workflows.

## What makes it credible

The repository has enough surface area to show that it has moved past novelty:

- a documentation site with security, deployment, observability, and operator runbooks,
- a demo path that shows the workflow end to end,
- release notes and changelog discipline,
- GitHub Actions and GitLab security-gate examples,
- Docker Compose and Helm deployment material,
- API-key/JWT auth, tool scopes, runtime policy bundles, audit events, rate limits, workspace quotas,
  and target URL validation.

The June 10 v0.9.0 release made the proof sharper: policy, audit, and abuse-protection handling moved
through shared gateway-core adapter boundaries instead of one-off local filters. The security-gate
examples rejected mutable image tags, and the release notes made validation commands inspectable.

The June 26 v0.9.1 release is the part that keeps the proof honest. It is a maintenance/security
release, not a feature launch. Runtime, Helm, MCP Registry, and install metadata moved to `0.9.1`.
The gateway-core adapters moved to `0.5.10`; Spring Boot moved to `4.0.7`; Spring AI moved to
`2.0.0`; Gradle moved to `9.6.0`; the docs stack moved to Astro `7.0.3`.

The security posture matters more than the version churn. The release overrides Spring Boot's Jackson
2 BOM to `2.22.0` so the runtime no longer resolves `jackson-databind` `2.21.4`. The Snyk workflow
now requires `SNYK_ORG`, fails when expected SARIF files are missing, and keeps monitor steps bounded
with explicit timeouts. Historical release notes were moved under `docs/releases/`, and the support
tables now say `>= 0.9.1` is active while `0.9.0` should be upgraded for dependency refresh. That is
what production-adjacent maintenance looks like: the proof ages, the repo catches up, and stale
claims get removed instead of defended.

That combination is exactly why this deserves a page here. The repository handles setup and usage.
This page explains why the project matters in the first place.

## How it connects to the writing

Expensive.](/posts/demos-are-cheap-production-mcp-is-expensive/) and the protocol explainer in
