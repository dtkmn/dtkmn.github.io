## What it is

`spring-boot-playground` is an internal starter candidate for controlled pilot adoption, not broad
platform rollout. It keeps `mvc-jpa` as the default path, supports `webflux-r2dbc` for teams with a
real reactive requirement, and leaves Kafka, Kafka Streams, and WebSocket integrations in examples
outside the starter contract.

## Modernized baseline

[PR #133](https://github.com/dtkmn/spring-boot-playground/pull/133) changes the Spring Boot plugin
from 3.5.15 to 4.1.0 in both starter templates and all three examples. The compatibility work includes
the Boot 4 test starters and package moves, Spring Boot starter dependencies for Flyway and Kafka,
and Jackson 3 imports where the WebSocket example needs them.

The JVM did not move with that PR. Java 21 remains the stable toolchain and builder baseline, and the
merged version policy still lists Java 25 as a future migration tranche.

## Hardened runtime

[PR #135](https://github.com/dtkmn/spring-boot-playground/pull/135) replaces the Alpine-based
Eclipse Temurin runtime stage in the two starter templates and three examples with a digest-pinned
`gcr.io/distroless/java21-debian13:nonroot` image. Those Dockerfiles declare `USER 65532:65532` and
use the distroless Java entrypoint through `CMD ["app.jar"]`.

The repository validator statically checks both template Dockerfiles for the distroless image family,
explicit non-root user, and `app.jar` command. The upstream runtime guidance also records the practical
trade-off: the production image has no shell or package manager, and services that need one require a
documented, tested exception.

## Two deliberate variants

The modernization preserves the starter's central decision. Use `mvc-jpa` for the lowest-friction
request/response path; use `webflux-r2dbc` only when non-blocking I/O provides a clear benefit and the
team is prepared for Reactor and reactive persistence. Both templates share the Spring Boot 4.1.0 and
digest-pinned distroless Java 21 baselines.
