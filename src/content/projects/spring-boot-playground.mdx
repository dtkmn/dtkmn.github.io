## What it is

`spring-boot-playground` provides service templates for controlled pilot adoption. It keeps `mvc-jpa`
as the default path, supports `webflux-r2dbc` for teams with a
real reactive requirement, and leaves Kafka, Kafka Streams, and WebSocket integrations in examples
outside the starter contract.

## Baseline

[PR #133](https://github.com/dtkmn/spring-boot-playground/pull/133) records the historical migration to
Spring Boot 4.1.0. The
[current version policy](https://github.com/dtkmn/spring-boot-playground/blob/main/docs/releases/version-policy.md),
updated September 2, 2026, specifies Spring Boot 4.1.1. Java 21 remains the stable toolchain and
builder baseline; Java 25 remains a future migration.

## Hardened runtime

[PR #135](https://github.com/dtkmn/spring-boot-playground/pull/135) uses digest-pinned
`gcr.io/distroless/java21-debian13:nonroot` images in both templates and three examples, with
`USER 65532:65532` and `CMD ["app.jar"]`.

The validator statically checks the template Dockerfiles for that image family, non-root user, and
command. The runtime has no shell or package manager; services that need one require a documented,
tested exception.

## Two deliberate variants

Use `mvc-jpa` for the lowest-friction request/response path. Choose `webflux-r2dbc` only when
non-blocking I/O provides a clear benefit and the team is prepared for Reactor and reactive persistence.
